1 · The daily workspace

src/App.tsx renders trip/date navigation, the vertical schedule, tasks, settings, and edit dialogs. Its mutate path builds a changed-field patch and retains a failed draft locally. src/MapPanel.tsx renders the map, markers, and connections; src/types.ts contains the browser's data and default layout/settings.

Product link: PRD → Places and Connections; Schedule and Linked Tasks.

2 · Identity and the API boundary

src/firebase.ts reads browser-safe Firebase Web configuration and sends authenticated requests to /api/tevel. server/http.ts verifies the ID token and email state, bounds the body, and dispatches the action. Never place the service-account private key in the browser configuration.

Product link: Spec → Persistence and Live Updates; Failure Modes and Security.

3 · Shared content and personal membership

server/service.ts implements TevelService.execute for trip/item/layout/share actions. Membership checks gate edits; transactions compare changed-field versions. The shared trip's owner and content are separate from each user's saved membership and layout.

personalRemove revokes one membership; globalDelete revokes every membership and sharing access. cleanup applies personal retention and purges unretained content. server/store.ts adapts these operations to Firestore Admin transactions.

Product link: PRD → Retention and Deletion.

4 · Realtime reads and independent checks

src/App.tsx uses Firestore onSnapshot for the active workspace. firestore.rules independently controls which authenticated account can read each trip, item, and layout; direct browser writes are denied.

tests/backend.test.ts checks domain operations, tests/rules.test.ts checks unauthorised client access, and tests/backend.integration.test.ts exercises real emulator transactions and live observations. Emulator checks support the implementation; production authentication and a real browser flow need their own evidence.

A small practice to reuse

Trace an ownership rule before changing it.

  1. Read the personal/global deletion behaviour in the PRD.
  2. Locate personalRemove and globalDelete in the service.
  3. Find a backend test demonstrating each scope, then read the independent Firestore rule.
  4. Explain which data belongs to the trip and which belongs to the person; run the relevant test if you choose to investigate a change.

This is an optional reference practice. No completed reflection, mastery, or hands-on review is claimed. Record only an actual activity in the checklist; personal reflections belong in the ignored learner profile.
